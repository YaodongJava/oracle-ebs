# 第 1 周：组织边界与端到端流程

> 本周定位：先建立“谁拥有交易、谁计算成本、谁生成会计”的全景图。本周只做纸面推演，不配置系统、不运行 SQL，也不背菜单路径。

## 学习目标

完成本周后，你应能够：

1. 区分 Ledger、Legal Entity、Operating Unit（OU）、主物料组织和库存组织。
2. 说明 PO、RCV、INV、BOM、WIP、CST、SLA、GL 各自处理什么，不处理什么。
3. 用一张图同时表达实物流、成本流和会计流。
4. 区分“业务已完成、已成本、已会计、已转 GL、已导入、已过账”。
5. 解释子账期间与 GL 期间为何需要分别检查。
6. 使用贯穿案例完成一次从采购到完工、再到总账的纸面追踪。

## 概念讲解

### 1. 企业结构不是一棵简单的组织树

| 对象 | 本周需要掌握的职责 | 不要误解为 |
| --- | --- | --- |
| Ledger | 决定科目表、本位币、会计日历和 SLA 方法，承载 GL 日记账与余额 | OU 或库存仓库 |
| Legal Entity | 法定、税务与法律责任主体 | 日常子账权限边界 |
| Operating Unit（OU） | PO、AP、AR、OM 等子账交易和数据访问边界 | 法人或库存估价边界 |
| 主物料组织 | 集中定义和维护共享物料属性；成员组织引用主物料定义 | Ledger 或 OU |
| 库存组织（IO） | 持有库存数量，执行 INV/WIP/BOM 制造交易，并承载组织级成本参数 | 仅仅一个物理仓库 |

一个 OU 可以关联多个库存组织。主物料组织也属于库存组织模型，但它承担主数据中心角色；是否同时发生交易取决于企业设计，不能仅凭“主组织”名称判断。

### 2. 端到端链路要分成三种流

```text
业务与实物流：PO → RCV Receipt → RCV Delivery/INV → WIP Issue → WIP Completion
成本处理流：    采购/库存/WIP 事务 → CST Cost Processor → 成本分配
会计处理流：    成本分配 → SLA Event/Entry → Transfer → GL Import → Post
```

- **PO** 定义采购订单、价格和分配，通常处于 OU 业务边界。
- **RCV** 记录收货、检验、交付、退货和更正。Receipt 到 Receiving Inspection 不等于已进入库存现有量；Delivery 才把合格物料交付到目标库存组织/子库。
- **INV** 记录库存数量事务，如接收入库、杂项收发和组织/子库转移。
- **BOM/Routing** 是制造结构和工艺定义，必须在创建、执行 WIP 任务前准备好；流程图中的顺序表示追踪关系，不表示 BOM 在收货后才定义。
- **WIP** 记录工单、组件发退料、资源、外协、间接费、完工和关闭。
- **CST** 为库存和 WIP 业务事务计价并形成成本分配。
- **SLA** 根据业务事件和会计规则生成子分类账分录。
- **GL** 导入、审核和过账日记账，最终更新账簿余额。

### 3. “处理成功”必须说明成功到哪一步

```text
业务事务已处理
  → Costed（已成本）
  → Accounted（已会计）
  → Transferred（已转 GL）
  → Imported（已导入日记账）
  → Posted（已过账）
```

前一状态不能证明后一状态。例如，库存数量已经增加，只能证明业务事务已处理；它不能证明成本、SLA 和 GL 已经完成。功能顾问回答问题时要说出具体阶段，避免只说“已经进系统”。

### 4. 期间决定交易和会计落在哪个时间边界

- Ledger 使用会计日历；各子账期间与 GL 期间分别控制。
- 一笔库存事务有业务日期，也会形成会计日期；两者都要落在允许处理的期间内。
- 月结通常先清理业务子账和接口，再完成成本、会计、转 GL 和对账，最后关闭 GL。
- Inventory 期间正式关闭后不能重开。本学习包没有训练环境，因此只设计关期顺序，不模拟实际关闭操作；遗漏交易以开放期间的受控更正/调整处理。

### 5. 功能顾问的追踪问题

面对任一成本问题，先连续回答五个问题：

1. 交易属于哪个 OU、库存组织和 Ledger？
2. 来源业务事件是什么，数量是否正确？
3. 事务是否已成本，使用什么成本方法和成本？
4. SLA 是否生成并转入 GL？
5. 最终过账期间、科目和金额是什么？

## 贯穿案例任务

### 固定案例资料

纸面企业“华东离散制造有限公司”采用以下简化结构：

| 对象 | 案例值 |
| --- | --- |
| Primary Ledger | CN_PRIMARY，CNY，本月为 AUG-26 |
| Legal Entity | 华东离散制造有限公司 |
| Operating Unit | CN 制造 OU |
| 主物料组织 | ITEM_MASTER |
| 制造库存组织 | M1 |
| 物料 | 原料 A、原料 B、半成品 S、成品 F |

成本数据本周只作为流程标签使用：A 标准成本 10、采购价 11；B 标准成本 4；S 标准成本 20；F 标准成本 52。

### 纸面交易

1. 在 CN 制造 OU 下采购 A，订单价为 11。
2. A 先收至 Receiving Inspection，再交付到 M1 原料子库。
3. 创建 1 个 S 的工单，按标准结构领用 3 个 B，记录资源与间接费并完工入库。
4. 创建 1 个 F 的工单，计划领用 2 个 A 和 1 个 S；实际领用 3 个 A，即多领 1 个 A；记录资源与间接费并完工。
5. 将上述事件依次标记为“业务已处理、已成本、已会计、已转 GL、已导入、已过账”。本周不计算具体分录和差异。

### 任务步骤

1. 画三条泳道：业务/实物流、成本处理流、会计处理流。
2. 在每个节点写出负责模块、所属组织边界、输入和输出。
3. 对 A 的采购收货和 F 的完工各画一条六阶段状态链。
4. 用一句话解释为什么“F 已经完工入库”仍不能证明 GL 已过账。

## 自测（8 题）

1. OU 与库存组织的核心区别是什么？
2. Receipt 与 Delivery 为什么不能视为同一事件？
3. 主物料组织是否必然不发生库存交易？
4. BOM/Routing 在链路中提供什么，不直接完成什么？
5. `Costed` 是否等于 `Posted`？请列出中间阶段。
6. 库存数量已增加，最少可以证明哪个阶段完成？还不能证明什么？
7. 为什么检查 GL 期间开放仍不足以保证库存事务可处理？
8. F 已完工但 GL 无记录时，应按什么顺序检查？

### 参考答案

1. OU 是 PO/AP/AR/OM 等子账交易与访问边界；库存组织持有库存数量并执行 INV/WIP/BOM 交易和组织级成本处理。
2. Receipt 可只进入接收/检验；Delivery 才将物料交付到库存组织或费用目的地。
3. 不必然；是否交易取决于企业设计。
4. 提供组件结构和工艺/资源基础；不直接生成领料、完工或 GL 过账。
5. 不等于。已成本之后还要已会计、已转 GL、已导入、已过账。
6. 至少证明业务数量事务已处理；不能证明已成本、已会计或已过账。
7. 子账期间与 GL 期间分别控制，库存期间可能未开放或已关闭。
8. 依次查业务事务、成本处理、SLA 会计、转 GL、Journal Import 和 GL Post。
